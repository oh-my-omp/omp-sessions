# omp-sessions

English | [简体中文](README.zh-CN.md)

- **`session://` scheme (read, grep, glob over `~/.omp/agent/sessions`)**
  - Scheme registration — Does: registers a read-only `session` scheme in omp's process-global internal-URL router, reachable from main sessions, subagents and light mode; it never replaces an omp-owned scheme or another owner's handler. When: once when the extension loads. Example: on conflict omp logs `omp-sessions: <reason>`.
  - URL grammar — Does: the full `session://` grammar is part of omp's own URL reference; the system prompt's `session://` line points to it. When: when the model reads it. Example: `read help://read/urls`.
  - Finding sessions — Does: omp's `archive` eval global lists projects and sessions, searches prompts and returns recaps; its session ids work in every `session://` URL and as `sid` in `session_query`. `session://find` and the `sessions.jsonl` routes are gone; prompt search, titles and recaps are only in `archive`. When: in an eval cell. Example: `archive.sessions({ project: "*", limit: 5 })`, `archive.recaps({ project: "*" })`.
  - Timeline — Does: renders a session's active branch with user, developer, thinking, assistant text, IRC, task dispatches and subagent results in full, and every other tool call as one line `tool(args) status #<result entry> // intent`. When: on read of the URL. Example: `session://01a1f4a1/timeline`.
  - Entries, events and raw file — Does: shows one entry in full, the same events as JSONL, or the session file itself. When: on read of the URL. Example: `session://01a1/entry/<id>`, `session://01a1/events.jsonl`, `session://01a1/raw.jsonl`.
  - Subagents, artifacts and local files — Does: repeats the tree for each subagent and exposes the session's `artifact://` and `local://`. When: on read of the URL. Example: `session://01a1/agents/ReadmePeers/timeline`, `session://01a1/artifacts/4`, `session://01a1/local/readme-contract.md`.
  - Filters and jq — Does: filters `timeline` and `events.jsonl` by event kind, group, `call:<tool>`, `marker:<what>` or exclusions and by time window, and runs jq with `?q=` on `events.jsonl`. When: when the URL carries the query. Example: `session://01a1/timeline?type=thinking,irc&since=2h`, `session://01a1/events.jsonl?q=<jq>`.
  - grep tree — Does: exposes one traversable tree for `grep`/`glob`, aliased `session://here/…` for the current project, with `session://type/<filter>/<path>` as the filter form that survives a glob. When: when `grep` or `glob` walks a `session://` path. Example: `grep` over `session://here/2026-11-20/*/timeline`; `session://projects/<bucket>/<YYYY-MM-DD>/<full-id>/agents/<AgentId>/timeline`.
  - Read process — Does: each read starts one process of the Rust engine `omp-sessions-engine`, which parses the session files the URL needs, answers with the rendered text and exits; omp holds only that text. When: on every `session://` read, `grep` and `glob`, and every `session_query` `agents` or `events` call. Example: omp's log gets one `omp-sessions engine` line per request with `op`, `ms`, `transcripts`, `bytes`, `cache` and `peakRssBytes`.
- **`session_query` tool (JS/Python and SQL over the same history)**
  - Tool registration and activation — Does: registers `session_query` inactive, then activates it through `applyActiveTools` in canonical order (builtins first in registry order, others by name) so the base system prompt stays identical across `/restart`. When: registered at load; activated on `session_start`. Example: `(await tool.session_query({ action: "agents", sid: "01a1" })).details` in an eval cell.
  - `agents` / `events` actions — Does: return a session's transcript tree, or a page of one transcript's active-branch events. When: when an eval cell calls the action. Example: `tool.session_query({ action: "agents", sid: "01a1" })` → rows `sid agent parent file bytes modified`.
  - `sql` action and schema `src` — Does: runs DuckDB SQL with the relations its parse tree names (`src.files`, `src.entries`, `src.events`, `src.transcripts`, `src.sessions`, plus rows passed in `tables`) built from the session files at call time and dropped after the call. When: on each `sql` call. Example: `tool.session_query({ action: "sql", from: { sids: ["01a1"] }, query: "select count(*) from src.events" })`.
  - Query process — Does: runs the session's SQL in one engine process per omp session; tables, views and macros created in schema `main` live only in that process (at most 4 GB in memory, spilling to a private temp directory removed when the process ends), so their memory is the query process's, not omp's. When: started by the session's first `sql` or `export` call and reused by the later ones; ended on `session_switch` (`/new`, resume, fork), on `session_shutdown`, and when a call arrives from another omp session. Example: `CREATE TABLE main.slow AS SELECT …` reused by the next call.
  - Query process exit — Does: when the query process exits unexpectedly (killed or crashed), the call in flight, or else the next call, fails with `engine_exited` and says the tables, views and macros in `main` are lost; the call after that starts a new process with an empty `main`. When: after the process is gone. Example: `session_query sql failed: engine_exited: the query process exited (signal SIGKILL); the tables, views and macros in main are lost`.
  - SQL limits — Does: refuses COPY, EXPORT, ATTACH, INSTALL, LOAD, SET, PRAGMA, CALL and other engine or file statements; SQL reads files only below the sessions directory and writes none. When: before each `sql` statement runs. Example: `ATTACH 'x.db'` is refused.
  - `export` action — Does: writes one query result to a parquet, csv or json file the caller names, never below the sessions directory. When: on an `export` call, which asks for write approval (every other action is `read`). Example: `tool.session_query({ action: "export", query: "select …", path: "/tmp/turns.parquet", format: "parquet" })`.
  - Direct-call output cap — Does: shows `details` as JSON text in a direct call only when it fits in 8192 characters. When: when `session_query` is called outside eval. Example: `sql: more than 8192 chars of JSON in details; call from eval and read .details`.
  - `help://session_query/actions` and `help://session_query/sql` — Does: document each action's rows and the `src` relations, persistence and allowed SQL. When: when the model reads them; the description's last lines point to them. Example: ``A view over `src` stops working after the call; keep results with `CREATE TABLE … AS`.``
- **Engine binary and cold cache**
  - Engine binary — Does: runs `engine/bin/omp-sessions-engine` inside the plugin package. When the package has none, the first call downloads this platform's asset from the GitHub Release of the plugin's version (`v<version>`) and checks its sha256 against that Release's `digests.json` before using it; later calls use the downloaded file. Platforms: `darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64`, `win32-x64`, `win32-arm64`. When: on the first `session://` read or `session_query` call after install or update. Example: `https://github.com/oh-my-omp/omp-sessions/releases/download/v<version>/omp-sessions-engine-darwin-arm64`.
  - `engine_unavailable` — Does: fails the call with the reason the engine binary could not be had, and the next call tries again; nothing partial is written. `unsupported_platform`: omp runs on a platform outside the six, where omp-sessions does not work. `not_built`: the Release of this version has no engine assets yet (they are uploaded after the release, `digests.json` last); retry once the Release lists them. `download_failed`: GitHub could not be reached or answered with an error; retry when it can be reached. `digest_mismatch`: the downloaded asset or `digests.json` does not match; retry, and report it if it persists. When: when a call needs an engine process and none can be started. Example: `session://: engine_unavailable: not_built: …`, `session_query sql failed: engine_unavailable: download_failed: …`.
  - Cold cache — Does: keeps the engine's parse of a transcript whose last message is more than 24 hours old, so later reads and queries of it skip parsing; an entry is used only while its session file is unchanged. The whole directory can be deleted at any time; that only makes the next reads slower. When: on the first read or query of such a transcript. Example: `omp-sessions` under omp's agent cache root, by default `~/.omp/agent/cache/omp-sessions`.
- **UI language**
  - Tool label — Does: shows the label in English or Chinese; descriptions, topics and results stay English. When: when the tool is registered. Example: `Session Query` / `会话查询`, chosen by `OMOMP_LANG`, then `LC_ALL`/`LC_MESSAGES`/`LANG`.
